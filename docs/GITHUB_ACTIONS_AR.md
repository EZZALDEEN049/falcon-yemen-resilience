# تعليمات التنفيذ في GitHub — دون PowerShell

## 1) Reproduce and Test
يبدأ تلقائيًا مع رفع الملفات إلى `main` أو يدويًا من `Actions → Reproduce and Test → Run workflow`.
يقوم باختبارات الرفض الآمن وإعادة إنتاج المؤشرات والأشكال من المواد المرفقة. حمل `reproduced-evidence` من قسم `Artifacts`.

## 2) Acquire Native IODA
شغّل workflow يدويًا واختر `FALCON_2020`. سيتم تنزيل استجابات API الأصلية (إن توفرت) لأربع كيانات، وحفظ JSON وCSV وmanifest كملفات Artifacts خاصة ضمن المستودع.
فشل/نقص API ممكن. يفشل العمل عند عدم الحصول على أي بيانات، وقد تظهر نجاحات جزئية: تفقد `manifest.json` و`validation_status.json`، خصوصًا عند رفض عناوين datasource أو غياب التغطية الزمنية. لا تنقل القيم إلى المخطوطة إلا بعد التحقق اليدوي من بنية الإشارة ودقة نافذتي الدراسة.

## 3) Historical BGP Discovery
شغّله يدويًا للشبكة `30873` أو `12486` وحدد نقطة جمع `rrc00`/`rrc01`/`rrc04`. يعتمد على حاوية CAIDA الرسمية ويتطلب الوصول إلى الوسيط الشبكي من GitHub runner. المخرج **قائمة مرشحة** لبادئات كانت ظاهرة في RIB بتاريخ 9 يناير 2020؛ وليس إعادة بناء كاملة لمسارات BGP أو إثبات فشل الكابل.
يرفض السكربت نتائج فارغة، ويمنع تحليلات المسارات حتى يتم التحقق من RIB كامل ورسائل A/W ومن استمرارية المراقبين عبر الزمن.

## القاعدة الأخلاقية
`success` في GitHub Actions ≠ إثبات صحة الاستنتاج العلمي. أبقِ المستودع خاصًا. استخدم روابط Artifacts الداخلية فقط، ولا تنشر بيانات أطراف ثالثة خلاف شروطها.

## 4) Full Research Pipeline — التشغيل الشامل بزر واحد
بعد رفع المشروع داخل مستودع خاص، افتح Actions → Full Research Pipeline → Run workflow.
اختر FALCON_2020، واترك Discover BGP مفعّلاً للبحث عن بادئات AS30873 وAS12486 من جامع rrc00. ينفذ GitHub ثلاث مهام مستقلة: الاختبارات وإعادة الحسابات، وطلب IODA، واكتشاف BGP. النتائج في Artifacts الخاصة بكل مهمة. لا يُعد نجاح التشغيل إثباتًا أن بيانات المصدر كاملة أو أن الدراسة أصبحت جاهزة للنشر.
